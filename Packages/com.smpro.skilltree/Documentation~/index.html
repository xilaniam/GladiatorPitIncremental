SMPro Skill Tree

A data-driven skill, talent, upgrade and research tree system for Unity 6. One asset holds the whole tree, and game code reads the results as stats. Adding or changing a node needs no new script, asset or scene object.

Unity 6000.0+ Runtime deps none UI deps PrimeTween, uGUI Tests 37 edit-mode Per-frame GC 0 allocations

What it offers

The package covers the whole loop: authoring a tree, buying nodes, turning levels into game numbers, showing the tree, saving it, and checking it for mistakes.

One tree asset

Nodes, layout, costs, requirements and effects all live in one SkillTreeDefinition. There are no per-node assets or hand-placed scene objects.

Computed stats

Every number a node changes is a stat, rebuilt from node levels. Purchase order never matters, and a save is just the levels.

Pluggable effects

Modify Stat, Unlock Feature, Grant Tag, Unity Event and Composite are built in. A custom effect is one class.

Conditions and costs

Gate nodes on points spent, tags or stat values. Price levels with Flat, Linear, Exponential or Table curves.

Features

Behaviour such as an ability is a SkillFeature component that a node switches on. Upgrading it is an ordinary stat change.

Reveal rules

Nodes can be always visible, appear when a parent starts, appear when ready, or show as a mystery "?" until they can be bought.

Any currency

Any component that implements ICurrencyWallet is the wallet. Nodes can use different currencies.

Save and respec

Saves are {nodeId: level} JSON, with optional PlayerPrefs or file saving. There are full and single-node refunds, at any refund percentage.

Generated UI

A uGUI view builds every node and link from the asset, with a tooltip, pan and zoom, and a style asset.

Editor tools

A graph editor, a balance table with CSV export, live validation, and a Play-mode debugger for stats and nodes.

How it works

The definition never changes at runtime. The controller holds the only mutable state, the level of each node. Everything else is derived from those levels.

A purchase, step by step

  1. CanPurchase(id) checks, in order: the node exists, it isn't maxed, its requirements are met, its conditions pass, and the wallet can pay. It returns the first thing that fails.
  2. The wallet spends the cost of the next level, in the node's currency.
  3. The level goes up by one, and every effect on the node gets Apply(context, newLevel).
  4. Modify Stat replaces its modifier with the one for the new level. The stat recalculates and raises StatChanged if its value changed.
  5. The controller raises NodeLevelChanged and TreeChanged, and saves if a save provider is set.

Auto-buyers, tests, console commands and the UI all use this same method. Nothing else changes levels.

How a stat gets its value

value = clamp( (base + Σ Flat) × (1 + Σ PercentAdd) × Π Multiply , min, max )

An Override modifier replaces the whole formula. Integer stats are rounded half away from zero. Modify Stat scales with level: Flat and PercentAdd use value × level, Multiply uses value ^ level (×1.2 per level compounds to 1.2, 1.44, 1.73), and Override uses the value as is. An optional per-level table replaces the formula.

Temporary buffs are modifiers with an expiry time. The controller's Update removes them when they run out.

Node states

Every node is in exactly one state, worked out from levels, requirements, conditions and its reveal rule. The UI only draws the state; it never decides it.

Data model

A tree is one ScriptableObject. Effects, conditions and cost curves are stored inline with [SerializeReference], so each node is complete inside the asset.

Node fieldPurpose
idStable key for saves and requirements. Renaming a node never breaks a save.
displayName, flavourText, iconWhat the player sees.
positionLayout in tree units; the UI places nodes from it.
maxLevel, cost, currencyIdHow many times it can be bought, and the price of each level.
requirementsOther nodes and the level each must reach.
conditionsExtra gates: points spent, tag owned, stat at least a value, or your own.
effectsWhat buying a level does.
reveal, tagsWhen it becomes visible, and labels for styling or queries (keystone gets the highlight).

Stats are defined on the tree with an id, display name, base value, min, max, integer flag and display format (number or percent).

Performance

Everything is event-driven. The only work done every frame is the controller's stat tick, which does nothing unless a temporary buff is active. Every path that runs often allocates no memory, so it causes no garbage-collection spikes.

Measured in Unity 6000.0.40f1 (Editor, Mono) on an AMD Ryzen 7 5800H. Times are averages over many calls; allocations were counted with Unity's GC.Alloc recorder. A built player with IL2CPP is usually faster than the editor.

Implement it in your game

1. Create the tree

Create ▸ SkillTree ▸ Skill Tree Definition. Add your stats in the Inspector, for example player.damage with a base of 10. Double-click the asset to open the graph. Right-click ▸ Add Skill Node, give it effects from the type menu, and drag from Unlocks to Requires to link nodes.

2. Add the controller and a wallet

Put a SkillTreeController on any GameObject and assign the tree. For the wallet, use SimpleWallet or your own economy class:

C# 
public class Economy : MonoBehaviour, ICurrencyWallet
{
    long gold;
    public event Action<string> BalanceChanged;

    public bool CanAfford(string currency, long amount) => gold >= amount;
    public bool TrySpend(string currency, long amount)
    {
        if (amount > gold) return false;
        gold -= amount;
        BalanceChanged?.Invoke(currency);
        return true;
    }
    public void Add(string currency, long amount) { gold += amount; BalanceChanged?.Invoke(currency); }
}

3. Read stats in game code

Add a StatRef field, then pick the tree and stat in the Inspector. It works on prefabs too, and has a value even before the controller starts.

C# 
using SMPro.SkillTree;

public class Spear : MonoBehaviour
{
    [SerializeField] StatRef damage;
    [SerializeField] StatRef critChance;

    float RollDamage() => Random.value < critChance.Value ? damage.Value * 2f : damage.Value;
}

4. Turn behaviour on with a feature

Give a node an Unlock Feature effect with an id, and put a component with the same id in the scene. A feature that spawns later still starts unlocked.

C# 
public class ChainLightning : SkillFeature
{
    [SerializeField] StatRef chance, jumps, damagePercent;

    protected override void OnUnlocked() => GameEvents.SpearHit += OnSpearHit;
    protected override void OnLocked()   => GameEvents.SpearHit -= OnSpearHit;

    void OnSpearHit(Enemy target, float damage)
    {
        if (Random.value < chance.Value) Arc(target, jumps.IntValue, damage * damagePercent.Value);
    }
}

Upgrades to the feature are ordinary Modify Stat effects on chain_lightning.jumps and the other stats it reads. The feature itself needs no upgrade code.

5. Temporary buffs

C# 
attackInterval.AddTemporary(ModifierKind.Multiply, 0.5f, duration: 5f, source: this);
attackInterval.RemoveModifiers(this);   // end it early

6. Save and load

Set the controller's Save Provider to PlayerPrefs or File, and it loads on start and saves after every change. To fit your own save system, store the JSON yourself:

C# 
string json = controller.CaptureState().ToJson();           // {"treeId":"...","levels":[...]}
controller.RestoreState(SkillTreeState.FromJson(json));    // unknown ids ignored, levels clamped
controller.ResetTree(refundPercent: 0.5f);                    // respec with a 50% refund

Extend it

Each extension is one class, and it shows up in the Inspector's type menu after compiling.

C# 
[Serializable, SkillEffectMenu("My Game/Extra Spawn Chance")]
public class ExtraSpawnChanceEffect : ISkillEffect
{
    public float chancePerLevel = 0.1f;

    public void Apply(SkillEffectContext ctx, int level) => ctx.Get<EnemyManager>().ExtraSpawnChance = chancePerLevel * level;
    public void Remove(SkillEffectContext ctx) => ctx.Get<EnemyManager>().ExtraSpawnChance = 0f;
    public string Describe(SkillTreeDefinition tree, int level) => $"{chancePerLevel * level:P0} chance to spawn an extra enemy";
}

[Serializable]
public class PlayerLevelCondition : ISkillCondition
{
    public int level = 10;
    public bool IsMet(SkillTreeController tree) => tree.GetService<Player>().Level >= level;
    public string Describe(SkillTreeDefinition tree) => $"Requires player level {level}";
}

[Serializable]
public class DoublingCost : CostCurve
{
    public long first = 1;
    public override long GetCost(int currentLevel) => first << currentLevel;
}

Apply receives the node's new level and sets the result for that level, so it gives the same answer on purchase and on load. ctx.Get<T>() returns a service registered with controller.RegisterService(x), or else the first scene object of that type. Validate(tree) is optional on effects and conditions; when present, its messages show in the editor.

UI module

SkillTreeView builds the tree at runtime from the definition, placing each node at position × spacing. It refreshes when the tree or the wallet changes. If that happens while the view is hidden, it waits until it is shown again.

SkillNodeViewIcon, level fill, level text, state tint, highlight, affordable indicator and button. Every part is optional. Animates hover and purchase.

To restyle, swap the node prefab or the style asset. Tooltip text is generated from the name, flavour text, each effect's current → next level line, the cost, and anything still required, so it can't drift from the numbers. NodeClicked and NodePurchased events let a game add sounds or effects. Turn off Purchase On Click to handle clicks yourself.

Editor tools

Graph window

Double-click a tree asset. Add, duplicate, delete and link nodes, and edit the selected node in the side panel. Links that would create a cycle, and duplicate links, are refused. Nodes with problems get a red or yellow border. Undo works throughout.

Table window

Every node in one grid: max level, cost curve values, currency and total cost to max. Shows the cost of maxing everything and exports to CSV.

Validation

Duplicate or missing ids, unknown or unreachable requirements, cycles, missing effect classes, unknown stats and missing icons. Shown in the Inspector and graph, and logged when the asset is imported.

Play-mode debugger

On the controller: grant currency, buy or refund nodes, max or reset everything, copy or load save JSON, and see every stat with its modifiers and the nodes they come from.

Case study: Gladiator Pits

The package was extracted from the skill tree of Gladiator Pits, an incremental game, and the game was then moved onto it.

BeforeAfter
40 hand-placed node objects in the scene40 entries in one tree asset; the shop is generated
25 variable assets and 38 effect assets27 stats and inline effects in the same asset
An ability framework with an upgrade enum and switch statements6 small feature components that read stats
Hunter's Frenzy overwrote two variables and restored themTwo temporary modifiers that expire on their own

Results. With every node maxed, all 27 values match the old system. A bot played the full game through the generated shop and bought all 152 levels in 66 rounds, the same as before the move, with no errors or warnings. Five node costs changed by 1 coin, because the old float maths was 1 coin too high (159,721 where 15000 × 2.2³ is exactly 159,720). The new costs are exact.

Good to know

  • Effects, conditions and cost curves are stored with [SerializeReference]. Before renaming or moving one of these classes, add [MovedFrom(...)], or trees lose that entry. The validator reports any entry whose class went missing.
  • As with any Unity component, a SkillFeature or wallet component must live in a file named after its class.
  • Stats belong to the tree (tree.Stats). They reset when entering Play mode, even with domain reload turned off.
  • Costs and balances are long. Exponential costs multiply in decimal, so they are exact, and they cap at the largest long instead of overflowing.
  • The UI assembly is skipped when PrimeTween is missing, so a project without it still compiles.
